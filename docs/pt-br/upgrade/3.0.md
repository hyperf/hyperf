# Guia de upgrade da versão 3.0

- A versão 3.0 modifica principalmente o `PHP`, a versão mínima é `8.0`
- O framework remove as `Doctrine Annotations` e usa `PHP8 Attributes` em seu lugar
- O framework adiciona um grande número de restrições de tipo para member variables

## Converta todas as annotations

**Nota: esta etapa só pode ser realizada na versão 2.2**

O script a seguir converterá todas as `Doctrine Annotations` em `PHP8 Attributes`.

```shell
composer require hyperf/code-generator
php bin/hyperf.php code:generate -D app
```

## Modifique a versão de todos os componentes Hyperf

Basta alterar `hyperf/*` no `composer.json` para `3.0.*`.

> O hyperf/engine não segue o número de versão do framework, então não é necessário modificá-lo, apenas certifique-se de que seja a versão ^2.1.0

Depois disso, você só precisa executar `composer update -o`, e o upgrade poderá ser concluído normalmente.

## Atualize o model do database

Como a classe base do model adicionou suporte a tipos para member variables, você precisa usar o script a seguir para atualizá-lo para a nova versão.

```shell
composer require hyperf/code-generator
php vendor/bin/regenerate-models.php $PWD/app/Model
```

## Logger

A versão 3.x do `monolog/monolog` usa os novos recursos do PHP8.1, então algumas classes precisam ser modificadas especificamente

Modifique `array $record` para `array|LogRecord $record` para ser compatível com a versão 3.x, o código de exemplo é o seguinte

```php
<?php

declare(strict_types=1);

namespace App\Kernel\Log;

use Hyperf\Context\Context;
use Hyperf\Coroutine\Coroutine;
use Monolog\LogRecord;
use Monolog\Processor\ProcessorInterface;

class AppendRequestIdProcessor implements ProcessorInterface
{
    public const REQUEST_ID = 'log.request.id';

    public function __invoke(array|LogRecord $record)
    {
        $record['extra']['request_id'] = Context::getOrSet(self::REQUEST_ID, uniqid());
        $record['extra']['coroutine_id'] = Coroutine::id();
        return $record;
    }
}

```

## Command

Após a versão `3.0`, a linha de comando tem um event listener habilitado por padrão, então quando um listener escuta o evento `Command` e executa `AMQP` ou outra lógica de multiplexação, o processo não conseguirá encerrar.

Solução

- método um:

Ao executar o command, adicione a opção `--disable-event-dispatcher`

- Método dois:

Adicione o listener

```php
<?php

declare(strict_types=1);

namespace App\Listener;

use Hyperf\Command\Event\AfterExecute;
use Hyperf\Coordinator\Constants;
use Hyperf\Coordinator\CoordinatorManager;
use Hyperf\Event\Annotation\Listener;
use Hyperf\Event\Contract\ListenerInterface;

#[Listener]
class ResumeExitCoordinatorListener implements ListenerInterface
{
    public function listen(): array
    {
        return [
            AfterExecute::class,
        ];
    }

    public function process(object $event): void
    {
        CoordinatorManager::until(Constants::WORKER_EXIT)->resume();
    }
}
```

## Inicie o server

A seguir, você só precisa iniciar o server, e poderá ver os códigos incompatíveis e modificá-los um por um.

- Adicionados tipos para as member variables de Consumer e Producer do AMQP
- O método `process` do Listener adiciona um tipo de retorno `void`
- A annotation `#[CircuitBreaker]` alterou o parâmetro `$timeout` para `$options.timeout`

## GRPC

O framework modifica o `Http status` retornado pelo `GRPC Server` para ser 200, de acordo com a especificação `GRPC`, e o `GRPC Server` retorna o `status code` correspondente. Atualize para a versão `3.x`, caso contrário, o outro lado não conseguirá analisar o erro normalmente quando a requisição for anormal.
