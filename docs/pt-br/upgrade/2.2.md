# Guia de upgrade da versão 2.2

A versão 2.2 adiciona principalmente a adaptação ao `PHP 8` e suporta annotations nativas.

## Modifique a versão dos componentes Hyperf

Basta alterar `hyperf/*` no `composer.json` para `2.2.*`.

> O hyperf/engine não segue o número de versão do framework, então não é necessário modificá-lo

Além disso, podemos executar `composer require "hyperf/ide-helper:2.2.*" --dev` para instalar o `hyperf/ide-helper`. Esse componente pode nos ajudar a sugerir os parâmetros que as annotations podem definir ao usar annotations nativas.

Depois disso, você só precisa executar `composer update -o`, e o upgrade poderá ser concluído normalmente.

## Modifique o script de testes unitários

Adicionada a opção `--prepend test/bootstrap.php`

```json
{
    "scripts": {
        "test": "co-phpunit --prepend test/bootstrap.php -c phpunit.xml --colors=always"
    }
}
```

## Instale a extensão pcntl

A nova versão da varredura de annotations usa a extensão `pcntl`, então certifique-se de que seu `PHP` tenha essa extensão instalada antes.

```shell
php --ri pcntl

pcntl

pcntl support => enabled
```

> Ao habilitar o `grpc`, você precisa adicionar `grpc.enable_fork_support= 1;` ao `php.ini` para suportar a abertura de processos filhos.

## AMQP

> Atenção aos usuários que usam AMQP, esta seção pode ser ignorada se não for o caso.

Como o componente `AMQP` foi totalmente atualizado e agora suporta multiplexação, há certas mudanças na configuração. Siga a configuração mais recente abaixo e modifique conforme apropriado.

```php
<?php

return [
    'default' => [
        'host' => env('AMQP_HOST', 'localhost'),
        'port' => (int) env('AMQP_PORT', 5672),
        'user' => env('AMQP_USER', 'guest'),
        'password' => env('AMQP_PASSWORD', 'guest'),
        'vhost' => env('AMQP_VHOST', '/'),
        'concurrent' => [
            'limit' => 1,
        ],
        'pool' => [
            // Number of connections opened at the same time
            // Because the new version of the connection supports multiplexing, it can achieve high concurrency with a very small number of connections
            'connections' => 2,
        ],
        'params' => [
            'insist' => false,
            'login_method' => 'AMQPLAIN',
            'login_response' => null,
            'locale' => 'en_US',
            'connection_timeout' => 3,
            'read_write_timeout' => 6,
            'context' => null,
            'keepalive' => true,
            'heartbeat' => 3,
            'channel_rpc_timeout' => 0.0,
            'close_on_destruct' => false,
            // The maximum value of idle channels in multiplexing. After this number is exceeded, the redundant limit channels will be closed.
            'max_idle_channels' => 10,
        ],
    ],
];

```

## Centro de configuração

> Usuários que usam o Centro de Configuração, por favor, note que esta seção pode ser ignorada se não for o caso.

O centro de configuração foi completamente refatorado nesta versão, certifique-se de reler cuidadosamente a documentação correspondente.

É necessário introduzir o componente `hyperf/config-center`, o comando é o seguinte:

```shell
composer require "hyperf/config-center:~2.2.0"
```

E introduzir o componente dependente do driver correspondente de acordo com o driver usado. Se você usa o `Apollo`, você precisa importar o componente `hyperf/config-apollo`, e os demais drivers são semelhantes.

Ao mesmo tempo, todas as informações de configuração relacionadas ao centro de configuração foram reunidas em `config/autoload/config_center.php`. Configure de acordo com a nova estrutura de configuração; se não houver esse arquivo, você pode executar o comando `php bin/hyperf.php vendor:publish hyperf/config-center` para criá-lo.

## Centro de serviço

Para usuários que usam o componente `hyperf/service-gonvernace`, como o adaptador `consul` foi removido desse componente, a nova versão precisa adicionar o componente `hyperf/service-governance-consul`. O comando é o seguinte:

```shell
composer require "hyperf/service-governance-consul:~2.2.0"
```

Usuários que usam `nacos` como driver do centro de serviço precisam introduzir o componente `hyperf/service-governance-nacos`, o comando é o seguinte:

```shell
composer require "hyperf/service-governance-nacos:~2.2.0"
```

## php-cs-fixer

Se você não precisa atualizar o `php-cs-fixer` para a versão `3.0`, você pode ignorar esta seção

1. Modifique o número da versão

```
"friendsofphp/php-cs-fixer": "^3.0"
```

2. Renomeie o arquivo .php_cs

Renomeie-o para `.php-cs-fixer.php` e modifique o código correspondente de acordo com os seguintes registros de alteração

```diff
- return PhpCsFixer\Config::create()
+ return (new PhpCsFixer\Config())

- 'commentType' => 'PHPDoc',
+ 'comment_type' => 'PHPDoc',
```

## A versão PHP 7.3 tem compatibilidade reduzida com o DI

> Usuários de versões mais recentes do PHP podem ignorar esta seção.

Nas versões `2.0` - `2.1`, para implementar o `AOP` atuando sobre objetos não gerenciados pelo `DI` (como objetos instanciados pela palavra-chave `new`), a implementação interna usava o componente `BetterReflection` para realizar isso. Embora isso trouxesse uma nova experiência de programação, também trouxe alguns problemas difíceis de superar, como segue:

- inicialização lenta do projeto sem cache de varredura
- `Inject` e `Value` não têm efeito em casos especiais
- o `BetterReflection` ainda não suporta PHP 8 (até o lançamento da 2.2)

Na nova versão, o uso do `BetterReflection` foi descontinuado, e o método de `varredura por subprocesso` foi adotado para resolver os pontos de dor acima, mas também há algumas incompatibilidades em versões inferiores do `PHP`:

Após iniciar a application com `PHP 7.3`, obtenho um erro semelhante ao seguinte:

```bash
PHP Fatal error: Interface 'Hyperf\Signal\SignalHandlerInterface' not found in vendor/hyperf/process/src/Handler/ProcessStopHandler.php on line 17

PHP Fatal error: Interface 'Symfony\Component\Serializer\SerializerInterface' not found in vendor/hyperf/utils/src/Serializer/Serializer.php on line 46
````

This problem is due to the fact that in `PHP 7.3`, the reflection is obtained by `subprocess scanning`, and a non-existing `Interface` is implemented in a certain class, which will cause an exception of `Interface not found` to be thrown. Higher versions of `PHP` do not.

The solution is to create the corresponding `Interface` and import it normally. The solution to the error reported above is to install the corresponding dependent components.

> Of course, it is better to upgrade to version 7.4 or 8.0

```bash
composer require hyperf/signal

composer require symfony/serializer
```

## Sistema de arquivos

> Para usuários que usam o sistema de arquivos, note que se não for o caso, você pode ignorar esta seção.

A partir da v2.2, o Hyperf suportará tanto a versão `v1.0` quanto a `v2.0` do componente `League\Flysystem`.

Se você usa a versão `v2.0` do `League\Flysystem`, os adaptadores correspondentes também precisam ser ajustados de acordo com a lista a seguir. Consulte o capítulo `Sistema de arquivos` para a documentação específica.

- Adaptador Alibaba Cloud OSS

```shell
composer require hyperf/flysystem-oss
````

- S3 adapter

```shell
composer require "league/flysystem-aws-s3-v3:^2.0"
composer require hyperf/guzzle
```

- Adaptador Qiniu

```shell
composer require "overtrue/flysystem-qiniu:^2.0"
```

- adaptador memory

```shell
composer require "league/flysystem-memory:^2.0"
```

- Adaptador Tencent Cloud COS

> A configuração básica deste adaptador é ligeiramente diferente da versão `v2.0` do componente `overtrue/flysystem-cos`, faça as modificações apropriadas de acordo com a configuração da versão mais recente.

```shell
composer require "overtrue/flysystem-cos:^4.0"
```
