# Guia de upgrade da versão 3.1

- A versão 3.1 muda principalmente a versão mínima do `PHP` para `8.1` e a versão mínima do `Swoole` para `5.0`.
- Introduzido o framework de testes `Pest`
- Adicionado o `hyperf/helper`, migrando as `funções helper sem namespace` de `Hyperf\Utils` para `hyperf/helper`.
- Alterada a forma como o `hyperf/config` carrega arquivos de configuração multinível para suportar a sintaxe `.`, por exemplo, `config('a.c')`

## Mudanças no pacote Utils

As funções helper no pacote utils original não tinham namespace adicionado, e podiam conflitar com funções em outros pacotes composer, então foram removidas e substituídas na 3.1.

Existem duas formas de lidar com isso

- Se nenhum outro pacote for introduzido na application que cause conflito de funções, você pode instalar diretamente o `hyperf/helper`, o pacote `helper` fornece funções helper sem namespace, igual ao pacote `utils` original.
- Namespaces são introduzidos onde as funções helper são chamadas, e podem ser refatoradas usando `rector` [documentação de refatoração aqui 🔎](https://github.com/orgs/hyperf/discussions/5635)

## Mudanças no carregamento de arquivos de configuração

Na 3.0, as configurações existiam com o `nome do arquivo de configuração` como key, enquanto na 3.1, os arquivos de configuração multinível do `hyperf/config` são carregados com `diretório relativo.Nome do arquivo de configuração` como key.

Suporte à sintaxe `.`, como `config('a.c')`.

Nesse sentido, é importante observar que os dois casos a seguir são tratados no projeto original

- Se o projeto 3.0 criou um subdiretório em `config/autoload`, por exemplo `config/autoload/sub/a.php`, o `config('a')` original precisa ser alterado para `config('sub.a')`.
- Se os nomes de arquivo de configuração no projeto 3.0 contêm `.`, como `config/autoload/a.b.php`, ao usar `config('a')` será retornada a estrutura a seguir, e se você também tiver um arquivo de configuração `config/autoload/a.php`, você também obterá o resultado após a mesclagem dos itens de configuração.
```php
return [
    'a.php config key' => 'a.php config value',
    'b' => [
        'a.b.php config key' => 'a.b.php config value',
    ]
];
```

## Outras mudanças

1. o componente `hyperf/metirc` não instala mais a dependência `prometheus` por padrão, então desenvolvedores que precisam usar o engine `prometheus` precisam executar o seguinte comando para carregar as dependências:

```bash
composer require promphp/prometheus_client_php
```

2. Mudanças no `withHeaders` de `Request` e `Response`

antes da v3.1, os dados originais eram salvos, semelhante a `array_merge`. Após a versão v3.1, todos os `headers` serão diretamente substituídos.

```php
<?php
// before v3.1 
$request->withHeader('foo', 1)->withHeader('bar', 2); // ['foo' => [1], 'bar' => [2]]
$request->withHeader('foo', 1)->withHeader('foo', 2); // ['foo' => [2]]
$request->withAddedHeader('foo', 1)->withAddedHeader('foo', 2); // ['foo' => [1, 2]]

$request->withHeaders(['foo' => 1])->withHeaders(['bar' => 2]); // ['foo' => [1], 'bar' => [2]]

// after v3.1
$request->withHeader('foo', 1)->withHeader('bar', 2); // ['foo' => [1], 'bar' => [2]]
$request->withHeader('foo', 1)->withHeader('foo', 2); // ['foo' => [2]]
$request->withAddedHeader('foo', 1)->withAddedHeader('foo', 2); // ['foo' => [1, 2]]

$request->withHeaders(['foo' => 1])->withHeaders(['bar' => 2]); // ['bar' => [2]]

$request->setHeader('foo', 1)->setHeader('bar', 2); // ['foo' => [1], 'bar' => [2]]
$request->setHeader('foo', 1)->setHeader('foo', 2); // ['foo' => [2]]
$request->addHeader('foo', 1)->addHeader('foo', 2); // ['foo' => [1, 2]]

$request->setHeaders(['foo' => 1])->setHeaders(['bar' => 2]); // ['bar' => [2]]
```

3. O valor de retorno do método `consumeMessage` do consumer `AMQP` foi ajustado para o enum Result

```php
<?php
// before v3.1
public function consumeMessage($data, AMQPMessage $message): string
{
    return Result::ACK;
}
// after v3.1
public function consumeMessage($data, AMQPMessage $message): Result
{
    return Result::ACK;
}
```
