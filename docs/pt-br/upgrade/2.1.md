# Guia de upgrade da versão 2.1

- A versão 2.1 adiciona principalmente o driver interno [hyperf/engine](https://github.com/hyperf/engine), permitindo que o framework `Hyperf` seja executado sobre `Swoole` ou `Swow`.
- Versão mínima do PHP alterada de 7.2 para 7.3

> O Swow é temporariamente uma versão de preview, use-o com cautela.

## Modifique a versão dos componentes Hyperf

Basta alterar `hyperf/*` no `composer.json` para `2.1.*`.

```json

        "php": ">=7.3",
        "ext-json": "*",
        "ext-openssl": "*",
        "ext-pdo": "*",
        "ext-pdo_mysql": "*",
        "ext-redis": "*",
        "ext-swoole": ">=4.5",
        "hyperf/async-queue": "2.1.*",
        "hyperf/cache": "2.1.*",
        "hyperf/command": "2.1.*",
        "hyperf/config": "2.1.*",
        "hyperf/constants": "2.1.*",
        "hyperf/contract": "2.1.*",
        "hyperf/database": "2.1.*",
        "hyperf/db-connection": "2.1.*",
        "hyperf/di": "2.1.*",
        "hyperf/dispatcher": "2.1.*",
        "hyperf/event": "2.1.*",
        "hyperf/exception-handler": "2.1.*",
        "hyperf/framework": "2.1.*",
        "hyperf/guzzle": "2.1.*",
```

Depois disso, você só precisa executar `composer update -o`, e o upgrade poderá ser concluído normalmente.

## Adicione a configuração optimize-autoloader

Porque o `Hyperf` precisa usar o `class_map` gerado pelo `composer` desde a `2.0`, o que exige que os usuários usem `-o` para otimização a cada atualização de dependências, mas muitos usuários nunca têm esse hábito.
Portanto, recomendamos adicionar a configuração correspondente ao `composer.json` para atender a essa necessidade.

```json
{
    "config": {
        "optimize-autoloader": true,
        "sort-packages": true
    }
}
```

## Modifique o SwooleEvent

A classe `Hyperf\Server\SwooleEvent` foi renomeada para `Hyperf\Server\Event` na `2.1`, então precisamos modificar o código correspondente na configuração `server.php`.

> O SwooleEvent será oficialmente removido na 3.0, altere-o para Event o mais rápido possível

```php
<?php

declare(strict_types=1);

use Hyperf\Server\Event;
use Hyperf\Server\Server;

return [
    'mode' => SWOOLE_BASE,
    'servers' => [
        [
            'name' => 'http',
            'type' => Server::SERVER_HTTP,
            'host' => '0.0.0.0',
            'port' => 9501,
            'sock_type' => SWOOLE_SOCK_TCP,
            'callbacks' => [
                Event::ON_REQUEST => [Hyperf\HttpServer\Server::class, 'onRequest'],
            ],
        ],
    ],
    'callbacks' => [
        Event::ON_BEFORE_START => [Hyperf\Framework\Bootstrap\ServerStartCallback::class, 'beforeStart'],
        Event::ON_WORKER_START => [Hyperf\Framework\Bootstrap\WorkerStartCallback::class, 'onWorkerStart'],
        Event::ON_PIPE_MESSAGE => [Hyperf\Framework\Bootstrap\PipeMessageCallback::class, 'onPipeMessage'],
        Event::ON_WORKER_EXIT => [Hyperf\Framework\Bootstrap\WorkerExitCallback::class, 'onWorkerExit'],
    ],
];
```

## Paginator

Porque o componente `hyperf/paginator` foi removido da dependência de `hyperf/database`. Portanto, quem usa o paginator no database também precisa introduzir o componente `hyperf/paginator`.

## Modifique a versão do DBAL

Se você usa o componente `doctrine/dbal`, você precisa atualizar para a versão `^3.0`.

## Remova o componente doctrine/common

O componente `doctrine/common` tem um conflito de dependência com `hyperf/utils`. Então esse componente precisa ser removido do `composer.json`.

```bash
# remove component
composer remove doctrine/common
# update
composer update "hyperf/*" -o
```

## Precauções

- Tente não alterar o engine de um projeto antigo para Swow. Se você quiser usar o Swow, tente em um novo projeto. Porque o Swow não é um substituto do Swoole, nem todos os cenários do Swoole conseguem encontrar equivalentes correspondentes no Swow.
