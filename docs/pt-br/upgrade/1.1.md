# Guia de upgrade da versão 1.1

A versão 1.1 adicionou muitas funcionalidades, mas algumas mudanças também envolvem o ajuste do skeleton Skeleton e o ajuste estrutural dos itens de configuração. Se você já investiu em um projeto para uso comercial e criou um projeto de application na versão 1.0 baseado no projeto Skeleton fornecido oficialmente, então você pode ajustar seu projeto skeleton de acordo com os pontos a seguir. Se você é um novo projeto, siga a documentação para criar um novo projeto com o comando `composer create-project hyperf/hyperf-skeleton` para usar a nova estrutura do skeleton.

## Atualize o Swoole para 4.4+

A versão 1.1 elevou a exigência mínima de versão do Swoole de 4.3+ para 4.4+. Existem alguns detalhes de uso entre essas duas versões. O Hyperf já foi adaptado em versões anteriores, então não há necessidade dos usuários do Hyperf se preocuparem com as diferenças. Aumentamos a exigência mínima de versão do Swoole principalmente para reduzir nosso legado histórico, e o Swoole 4.4, sendo a versão LTS (Long Term Support) do Swoole, também significa mais estabilidade e confiabilidade.

O Hyperf fará a detecção da versão do Swoole na inicialização, mas para unificar melhor as dependências das versões do Swoole em todos os lugares, recomendamos que você altere a dependência do Swoole no `composer.json` para `"ext-swoole": ">=4.4"`.

## Adicione a constante SWOOLE_HOOK_FLAGS

Adicione uma linha de definição de constante no arquivo de entrada da application `bin/hyperf.php` e no arquivo de entrada do teste unitário `test/bootstrap.php`, como segue:

```php
! defined('SWOOLE_HOOK_FLAGS') && define('SWOOLE_HOOK_FLAGS', SWOOLE_HOOK_ALL);
```

Referência: [Referência do arquivo de entrada](https://github.com/hyperf/hyperf-skeleton/blob/70062b7bbf29e23cda2f30680e02aa3b26ebd6f7/bin/hyperf.php#L11) [Referência do arquivo de entrada dos testes unitários](https://github.com/hyperf/hyperf-skeleton/blob/70062b7bbf29e23cda2f30680e02aa3b26ebd6f7/test/bootstrap.php#L20)

## Mova o arquivo config/dependencies.php e ajuste a estrutura de arquivos

Mova `config/dependencies.php` → `config/autoload/dependencies.php`, e remova o primeiro nível de `dependencies` no arquivo de configuração, como segue:

Estrutura de arquivo da 1.0:
```php
<?php
// config/dependencies.php document

return [
    'dependencies' => [
        FooInterface::class => Foo::class
    ],
];
```

Estrutura de arquivo da 1.1:
```php
<?php
// config/autoload/dependencies.php document

return [
    FooInterface::class => Foo::class
];
```

## Ajuste o conteúdo do arquivo config/container.php

Como a versão 1.1 ajustou a localização e a estrutura do arquivo `dependencies.php`, também precisamos ajustar o arquivo `config/container.php` para que o container de injeção de dependência possa funcionar corretamente. O `config/container.php` oferece uma forma mais simples de escrita, o `DefinitionSourceFactory` agrega muitos comportamentos padrão, você só precisa substituir o conteúdo do arquivo `config/container.php` pelo seguinte conteúdo:

> A função de cache de varredura (scan) de annotations está habilitada por padrão. Você pode modificar o primeiro parâmetro do `DefinitionSourceFactory` para desabilitar essa função

```php
<?php
/**
 * Initial a dependency injection container that implemented PSR-11 and return the container.
 */
declare(strict_types=1);

use Hyperf\Di\Container;
use Hyperf\Di\Definition\DefinitionSourceFactory;
use Hyperf\Utils\ApplicationContext;
use Psr\Container\ContainerInterface;

$container = new Container((new DefinitionSourceFactory(true))());
if (! $container instanceof ContainerInterface) {
    throw new RuntimeException('The dependency injection container is invalid.');
}
return ApplicationContext::setContainer($container);
```

## Ajuste o controller de WebSocket

Como a versão 1.1 ajustou as restrições de entrada de `onMessage` e `onOpen`, você precisa modificá-lo manualmente para `Swoole\WebSocket\Server`. O código específico é o seguinte

```php
<?php
declare(strict_types=1);

namespace App\Controller;

use Hyperf\Contract\OnMessageInterface;
use Hyperf\Contract\OnOpenInterface;
use Swoole\Http\Request;
use Swoole\Websocket\Frame;
use Swoole\WebSocket\Server as WebSocketServer;

class WebSocketController implements OnMessageInterface, OnOpenInterface
{
    public function onMessage(WebSocketServer $server, Frame $frame): void
    {
    }

    public function onOpen(WebSocketServer $server, Request $request): void
    {
    }
}
```

## Ajuste o ConfigProvider de componentes personalizados

Na versão 1.0, `scan.path` foi ajustado para `annotations.scan.path` na versão 1.1. Você precisa modificar a classe ConfigProvider de todos os componentes personalizados para se adaptar a essa mudança. Por exemplo, se seus componentes personalizados não envolvem a configuração da função de varredura de annotations, esse ajuste pode ser ignorado, como segue:

Estrutura do arquivo ConfigProvider para a 1.0:
```php
class ConfigProvider
{

    public function __invoke(): array
    {
        return [
            'scan' => [
                'paths' => [
                    __DIR__,
                ],
            ],
        ];
    }
}
```

Estrutura do arquivo ConfigProvider para a 1.1:
```php
class ConfigProvider
{

    public function __invoke(): array
    {
        return [
            'annotations' => [
                'scan' => [
                    'paths' => [
                        __DIR__,
                    ],
                ],
            ],
        ];
    }
}
```

## Ajuste o idioma de localização padrão

Se você usou o componente [hyperf/translation](https://github.com/hyperf/translation) anteriormente, então você precisa verificar o item de configuração `locale` no arquivo `config/autoload/translation.php`, como por exemplo, se for `zh-CN`, ele precisa ser alterado para `zh_CN`. Na versão 1.1, unificamos o valor dessa configuração.

## Ajuste as dependências do composer.json

Como queremos atualizar para a versão 1.1 dos componentes, e o projeto skeleton original depende por padrão da versão 1.0.x dos componentes, precisamos fazer alguns ajustes nas restrições da dependência, alterando as dependências de todos os componentes Hyperf originais de `~1.0.0` para `~1.1.0`. Após a modificação, você precisa executar `composer update` para atualizar as dependências para a versão 1.1.

Todas as dependências do Hyperf precisam ser atualizadas para a versão 1.1 para que estejam disponíveis, porque a 1.1 ajusta o mecanismo do ConfigProvider para adaptação de componentes.

## Concluindo o upgrade

Neste ponto, o upgrade para a 1.1 foi concluído, mas como cada arquivo interno do Hyperf pode ser sobrescrito através de DI, se você sobrescreveu alguns arquivos internos do framework ajustados neste upgrade, ainda precisará fazer alguns ajustes de acordo com a situação real.

Se você encontrar algum problema durante ou após o upgrade, por favor, acesse o [Github Issue](https://github.com/hyperf/hyperf/issues) para enviar seu issue, explicando o problema que você encontrou, e tentaremos ajudá-lo o mais rápido possível.
